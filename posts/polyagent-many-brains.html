Polyagent: one orchestrator, many brains

Polyagent is a ready tool, not a research bet — an MCP server you can register with Claude Desktop today. This post is the design rationale: why delegation beats monolithic agents, and how the loop-prevention layer makes delegation safe.

The problem: one agent can't do everything equally well

A single model instance asked to do security scans, code review, and long-context analysis will be mediocre at all three — and the token bill lands on whichever provider hosts it. Different models have different strengths and very different costs. Polyagent treats the model as a resource to route, not a single always-on brain.

Architecture in one line

Claude Desktop ⇄ MCP server (Polyagent) ⇄ external agents

Claude stays the coordinator; specialized work is delegated over an OpenAI-compatible endpoint to GLM, OpenAI, Anthropic, AWS Bedrock, Gemini, or Ollama Cloud. Agents are registered dynamically — add a provider config, the registry picks it up without code changes.

Pipeline modes

  • Sequential — each agent refines the previous one's output; useful for scan → triage → report chains.
  • Iterative — one agent loops until confidence criteria are met.
  • Parallel — independent agents run concurrently; results are merged by the coordinator.

Loop prevention — the part that actually matters

Untethered agents looping on their own output is the classic failure. Polyagent ships real gates, not vibes:

  • Max iterations per task — hard ceiling, no soft exceptions.
  • Confidence thresholds — the loop exits when quality criteria pass, not when tokens run out.
  • Human approval gates — defined actions pause for explicit approval before execution.

Streaming, metrics, and hardening

Output streams back through MCP as it's produced, so delegation doesn't feel like a stall. Every call is logged with error handling and metrics — which agent, which provider, how long, what it cost in tokens. Production hardening is boring on purpose: timeouts, retries, and explicit failure states instead of silent hangs.

Where it goes next

The registry is the growth surface: more specialized agents (dynamic analysis, docs synthesis, test-generation) land as configs, not forks. If you run Claude Desktop and have a favorite provider, the repo ↗ is open — issues welcome.
